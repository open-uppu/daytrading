### 1.2 เขตเวลา — จุดที่ต้องระวังที่สุด (มีหลักฐานยืนยัน)

timestamp ในไฟล์เป็น **เวลา local UTC+7 (Asia/Bangkok)** ไม่ใช่ UTC หลักฐาน 3 ชิ้นจากข้อมูลเอง:

1. **รอยต่อสุดสัปดาห์**: แท่งสุดท้ายของสัปดาห์คือ `2026-07-11 03:45` (วันเสาร์) และแท่งแรกของสัปดาห์ถัดไป คือ `2026-07-13 05:00` (วันจันทร์) — ถ้าเป็น UTC ตลาดทองจะปิดวันเสาร์ 03:45 UTC ซึ่งเป็นไปไม่ได้; ถ้าเป็น UTC+7 จะตรงกับ ปิดศุกร์ 20:45 UTC / เปิดอาทิตย์ 22:00 UTC (มาตรฐานตลาดทอง)
2. **เบรกประจำวัน**: ไม่มีแท่งในช่วง 04:00–05:00 (ตามเวลาที่เก็บ) = 21:00–22:00 UTC ซึ่งเป็นช่วง maintenance ของโลหะ
3. **Volume profile**: ปริมาณซื้อขายสูงสุดของ XAUUSD อยู่ที่ชั่วโมงที่เก็บ 19–22 = 12:00–15:00 UTC ซึ่งตรงกับ London/NY overlap (ช่วง liquidity สูงสุดจริง)

ดังนั้นรายงานนี้ **แปลงเป็น UTC ด้วยการลบ 7 ชั่วโมง** ก่อนจัด bucket ชั่วโมง/session ถ้าไฟล์ของคุณเป็น UTC จริง (ไม่ใช่ UTC+7) ให้เลื่อน label ทุกตัว +7 ชม. — **ข้อสรุปเรื่อง session จะเปลี่ยนทันที** จึงควรตรวจสมมติฐานนี้ก่อนใช้งานจริง

### 1.3 การติดป้ายผลลัพธ์ (forward-looking labeling)

สำหรับทุกแท่ง `i` ที่ผ่านเงื่อนไข (i ≥ 220 เพื่อให้ EMA200/ATR100 อุ่นเครื่องแล้ว, และมีแท่งอนาคตเหลือ ≥ 10 แท่ง) และทดสอบ **ทั้งสองทิศทาง**:

```
entry = close[i]
SL    = entry -/+ 1.5 * ATR14[i]      # k = 1.5
TP    = entry +/- 2.25 * ATR14[i]     # rr = 1.5 -> ระยะ TP = 1.5*SL
สแกนแท่ง i+1 .. i+50 (สูงสุด 50 แท่ง):
  - แตะ TP ก่อน SL  -> TP   (R = +1.5)
  - แตะ SL ก่อน TP  -> SL   (R = -1.0)
  - แตะทั้งคู่ในแท่งเดียวกัน -> นับเป็น SL (conservative)
  - ไม่แตะทั้งคู่ภายใน 50 แท่ง -> TIMEOUT, R = mark-to-market ที่ close ของแท่งสุดท้าย
```

ผลกระทบของกฎ conservative (แท่งเดียวแตะทั้ง TP และ SL): พบเพียง 0.56% (XAUUSD M15), 0.09% (BTCUSD M15), 0.55% (XAUUSD H1) ของ sample → ถ้านับฝั่ง TP แทน (optimistic) win rate จะสูงขึ้นไม่ถึง 0.6 pp ทุก dataset

จำนวน sample: แต่ละแท่งให้ 2 sample (long + short) → XAUUSD M15 = 8,522 sample จาก 4,538 แท่ง, BTCUSD M15 = 11,006 sample

### 1.4 ตัวชี้วัด (สูตรเดียวกับ `daytrad/core/indicators.py`)

- `EMA`: `ewm(span=period, adjust=False).mean()`
- `ATR(14)`: ค่าเฉลี่ยเคลื่อนที่แบบง่าย (SMA) ของ True Range 14 แท่ง = `max(H-L, |H-C_prev|, |L-C_prev|)` (ตามไฟล์ต้นทาง ไม่ใช่ Wilder smoothing) — หมายเหตุ: ตัวเลข ATR ในระบบเดิมอาจต่างจาก Wilder เล็กน้อย
- `RSI(14)`: SMA ของ gain/loss, ตัวส่วน loss มีพื้น 1e-5 กันหารศูนย์ (ตามไฟล์ต้นทาง)
- `body_ratio = |C-O| / (H-L)`, `upper/lower wick ratio` ตามนิยามใน `analyze_candlestick_patterns`

**Δ pp (adj ทิศทาง)** = ผลต่างเทียบ baseline *ของทิศทางเดียวกัน* (long เทียบ long, short เทียบ short) คอลัมน์นี้สำคัญเพราะข้อมูลช่วงนี้มี drift ขาขึ้น (long ชนะมากกว่า short ทุก symbol) ซึ่งจะทำให้ปัจจัยที่ไม่เกี่ยวกับทิศทางดูดีเกินจริงถ้าเทียบ baseline รวม

### 1.6 เกณฑ์ตัดสิน "หลักฐานพอ / บาง / ยังสรุปไม่ได้"

| เกรด | เงื่อนไข |
|---|---|
| **A = หลักฐานพอ** | n ≥ 200 · \|Δ\| ≥ 5 pp · **และ** ครึ่งแรก/ครึ่งหลังของช่วงข้อมูลให้เครื่องหมายเดียวกันและ \|Δ\| ≥ 3 pp ทั้งคู่ · **และ** subsample แบบ de-overlap (ทุกแท่งที่ 10) ให้เครื่องหมายเดียวกัน \|Δ\| ≥ 2 pp |
| B = หลักฐานบาง | ผ่าน n/Δ ตามเกณฑ์ แต่ผ่านการทดสอบความเสถียรเพียงข้อเดียว |
| C = ยังสรุปไม่ได้ | n < 200 หรือ \|Δ\| < 5 pp (หรือไม่ผ่านทั้งสองการทดสอบความเสถียร) |

**การทดสอบ de-overlap**: sample ที่ใช้แท่งติดกันจะทับซ้อนกันมาก (แท่ง i กับ i+1 มีช่วงแท่งอนาคตซ้อนกัน 49/50) จึงใช้เฉพาะแท่งที่ `i % 10 == 0` คำนวณซ้ำ ถ้าผลยังอยู่นิ่งแสดงว่าไม่ได้มาจาก sample ที่ซ้ำกันเกินไป

### 1.7 ข้อควรระวังเชิงตัวเลขที่ต้องอ่านคู่กับทุกตาราง

- ค่า p ที่รายงานเป็น **two-proportion z-test แบบ nominal เทียบ baseline ของ dataset** และ **ไม่ปรับ multiple testing** — ในรายงานนี้มีการทดสอบหลายร้อยครั้งต่อ dataset ดังนั้นควรใช้ p เป็นเพียงข้อมูลประกอบ **อย่าใช้ p < 0.05 ตัดสินใจเดี่ยว ๆ**
- ที่ baseline 38.5% และ n = 376, ช่วงความเชื่อมั่น 95% กว้างประมาณ ±5 pp → **Δ ที่เล็กกว่า 5 pp ใน bucket ที่ n < 1,000 คือ noise เป็นส่วนใหญ่**
- ตัวเลขทุกตารางคำนวณจาก sample ทั้งหมดของ dataset นั้น ๆ ไม่ได้แบ่ง train/test → ถ้าจะนำไปใช้จริงต้อง validate ซ้ำบนข้อมูลใหม่ (ดูข้อจำกัด ข้อ 7)

## 2. ผลรายปัจจัย — 3 symbol หลัก (M15)

อ่านตาราง: `n` = จำนวน sample ของ bucket, `win_rate` = % ที่ TP ก่อน SL, `avg R` = ผลตอบแทนเฉลี่ยต่อไม้เป็นหน่วย R (รวม timeout แบบ mark-to-market), `Δ pp` = ผลต่างจาก baseline ของ symbol, `Δ ครึ่ง1/ครึ่ง2` = Δ ของครึ่งแรก/ครึ่งหลัง (ตัวเลขที่ใช้ตัดสินความเสถียร), `เกรด` ตามเกณฑ์ 1.6

### 6.1 หลักฐานพอที่จะเอาไปใช้เป็น "ตัวกรอง" (negative filters)

ปัจจัยกลุ่มนี้ไม่ได้ทำให้คุณชนะมากขึ้น แต่ทำให้ **เลี่ยงไม้ที่แย่กว่าค่าเฉลี่ย** ได้ — ขนาดผล 1–10 pp ต่อไม้ และต้องยอมรับว่า sample ยังสั้น

**F1 — งดเข้าออเดอร์ที่แท่ง trigger ปิดในช่วง 15:00–16:00 UTC**

- 13 dataset ที่วิเคราะห์ได้: **ติดลบ 13/13** (Δ -10.0 ถึง -0.5 pp) · เครื่องหมายติดลบทั้งครึ่งแรกและครึ่งหลัง 11/13
- แรงสุด: EURUSD M15 -10.0 pp (n = 456), XNGUSD -9.2 pp (n = 376), GBPUSD M15 -7.4 pp (n = 456), XAGUSD -5.4 pp (n = 376), ETHUSD M15 -5.3 pp (n = 456), XAUUSD M15 -5.8 pp (n = 376)
- **ข้อแม้สำคัญ**: XAUUSD H1 (875 วัน, n = 1,184) แทบไม่มีผล (-0.5 pp) — อธิบายได้ว่าปรากฏการณ์นี้เกิด *ภายใน* ชั่วโมง 15:00–16:00 ถ้าเข้าที่ close ของแท่ง H1 (=16:00) ก็ไม่โดนผลนี้ → **ใช้กับการเทรด M5/M15 เท่านั้น**
- ไวต่อรูปทรงกรอบ: ที่ k=1.0 ผลหายไป (XAUUSD M15 +2.7 pp) แต่ที่ k=2.0 หรือ rr=2.0 แรงขึ้น (-12.9 / -11.3 pp)

### 6.3 ปัจจัยที่ **หักล้าง rulebook เดิม** (สำคัญ)

2. **long vs short ที่ดูเหมือน edge คือ drift ของช่วงข้อมูล** — ทุก symbol ในรายงานนี้ long ชนะ short (ETHUSD M15 long 41.2% vs short 36.1%; XAUUSD H1 long 41.4% vs short 37.4%) เพราะราคาขึ้นในหน้าต่างข้อมูล → **ห้ามสรุปว่า "ควร long เท่านั้น"** ให้ดูคอลัมน์ `Δ pp (adj ทิศทาง)` ที่หักผลนี้แล้ว

## 7. ข้อจำกัด (อ่านก่อนใช้ตัวเลข)

1. **ยังไม่หัก spread/commission** — ทุกตัวเลขเป็น gross R และ baseline win rate ≈ 40% หมายถึง avg R ≈ 0 ก่อนต้นทุน → **เมื่อหักต้นทุนแล้วทุกกรอบในรายงานนี้ติดลบ** ขนาดต้นทุนต่อไม้ประมาณ `2 × spread / (k × ATR)`; จาก ATR มัธยฐานจริง: XAUUSD M15 1R = 12.00 USD, BTCUSD M15 1R = 211.1 USD, ETHUSD M15 1R = 8.97 USD → spread ทอง 0.30 USD จะกิน ~0.050 R/ไม้ (สมมติตัวเลข spread ขึ้นมาเพื่อแสดงสเกลเท่านั้น — ข้อมูล spread ไม่มีในไฟล์)
2. **Survivorship / selection**: รายการ symbol มาจากระบบที่มีอยู่แล้ว ไม่ใช่ universe ที่สุ่มมา — symbol ที่เคยลบออกไปหรือไม่เคยเพิ่มจะหายไป นอกจากนี้ช่วงข้อมูลสั้นมาก (M15 = 56–69 วันซื้อขาย, M5 = 58–60 วัน, H1 = 722 วัน) ครอบคลุม regime เดียว (ทองขาขึ้น + crypto ขาขึ้น) → **ผล "long ชนะ short" และ "ATR สูงแย่" อาจเป็นลักษณะเฉพาะของ regime นี้**
3. **Overfitting / multiple testing**: มี ~70 bucket ต่อ dataset × 13 dataset ≈ 900 การทดสอบ ที่ p < 0.05 ตามคาดหมายเกิดได้ ~45 ครั้งจาก noise ล้วน ๆ การทดสอบครึ่งแรก/ครึ่งหลัง + de-overlap ช่วยกรอง แต่ **ไม่ใช่ out-of-sample จริง** (ข้อมูลทั้งสองครึ่งยังเป็น regime เดียวกัน) — ควรใช้ walk-forward กับข้อมูลใหม่ก่อนเทรดจริง
4. **Sample ทับซ้อน (overlapping labels)**: sample ที่ i กับ i+1 มีช่วงอนาคตซ้อนกันเกือบทั้งหมด → ค่า p และช่วงความเชื่อมั่นจะแคบกว่าความเป็นจริงหลายเท่า นี่คือเหตุผลที่เกณฑ์หลักคือ **ขนาดผล + ความสอดคล้องของเครื่องหมาย** ไม่ใช่ค่า p
5. **Timeframe/ความละเอียดของ intrabar**: การตัดสิน TP ก่อน SL ใช้ high/low ของแท่ง ถ้าในแท่งเดียวแตะทั้งคู่จะนับเป็น SL (conservative) — ข้อมูล tick/m1 ไม่มีในเครื่อง จึงประมาณลำดับเหตุการณ์ในแท่งไม่ได้
6. **เขตเวลา**: ถ้าไฟล์จริงเป็น UTC หรือ UTC+3 (broker time) ไม่ใช่ UTC+7 ตามหลักฐานในข้อ 1.2 → label ชั่วโมง/session ทั้งหมดต้องเลื่อน และ **ข้อสรุป F1/F2/F4 อาจเปลี่ยน**
7. **คุณภาพข้อมูลบาง symbol**: EURUSD/GBPUSD M15 มี volume = 0 ทั้งไฟล์, EURUSD มี OHLC ซ้ำ 1,640 แถว และ range = 0 ถึง 100 แท่ง → ผลของ symbol เหล่านี้เชื่อถือได้น้อยกว่า XAUUSD/BTCUSD/ETHUSD
8. **ไม่มี trade log จริงให้เทียบ**: journal มีเพียง 9 ไม้ paper (2026-11-08, ขาดทุนทั้ง 9 ไม้ รวม -$24.51 จากทุน $484.55) และ trade autopsy 3 ไฟล์ที่ดูเหมือนข้อมูลตัวอย่าง (ราคา/เวลาไม่ตรงกับ CSV) → **ไม่สามารถ validate ปัจจัยกับผลเทรดจริงได้** (n = 9 น้อยเกินไป)
9. **กรอบเดียว ไม่ได้ทดสอบ trailing/partial exit** — ระบบเดิมอ้างว่ามี trailing break-even ซึ่งเปลี่ยน win rate ได้มาก (ตัดไม้ขาดทุนให้เป็น breakeven) รายงานนี้ไม่ได้จำลองส่วนนั้น → ตัวเลข 38–40% ไม่ได้ขัดกับ "win rate 80%" ของระบบที่ใช้ trailing เพราะนิยามต่างกัน

### 8.4 สิ่งที่ยังไม่ได้ทำ (งานต่อไป)

- Walk-forward / out-of-sample บนข้อมูลที่ยังไม่เคยเห็น (จำเป็นที่สุด)
- หัก spread จริงจาก MT5 bridge แทนการสมมติ
- ทดสอบ trailing break-even และ partial TP (ระบบเดิมอ้างว่าได้ win rate 80%+ จากส่วนนี้)
- ทดสอบ combo ที่ผ่านการคัดเลือกแบบ pre-registered เท่านั้น (ตอนนี้ combo ใน JSON เป็น exploratory)
- ตรวจว่า "ชั่วโมง 15 UTC" เป็น London 4pm fix จริงหรือเป็น artifact ของแหล่งข้อมูล (ทดสอบกับข้อมูลจากโบรกเกอร์อื่นหรือ timeframe อื่นที่ granular กว่า M5)
