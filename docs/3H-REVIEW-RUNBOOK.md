# 3-Hour Review Runbook — ใช้ subagent แบบ fan-out ทุก 3 ชั่วโมง

> เป้าหมาย: ทุกรอบให้ทีม specialist วิเคราะห์ **แล้วปรับกลยุทธ์ถ้ามีหลักฐาน** โดย **ไม่หยุดการเทรด**
> ลูปที่ต้องวิ่งตลอด: `gold --mode=mt5 --continuous --no-loss-cutoff`
> เวลารวมทั้งรอบ: ~8–12 นาที (snapshot + fan-out + ปรับถ้าจำเป็น)

---

## Phase 0 — Snapshot (ผมทำเอง, ~1 นาที)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\trader\daytrad\scripts\dev_status.ps1
docker exec agentic_dev python3 /app/scripts/_procs.py
docker exec agentic_dev sh -c "grep -a -E 'HOLD|BUY|SELL|ORDER|Risk rejected' /app/artifacts/mt5_live.log | tail -n 20"
```

แล้วดึงแท่งเทียนจริงจาก bridge:
`http://localhost:8000/api/mt5/bars?symbol=XAUUSD&timeframe=M5`  (**ใช้ `timeframe=` เท่านั้น**)

ถ้าลูป MT5 ตาย → สตาร์ทใหม่ทันทีด้วยคำสั่งเดิม ห้ามปล่อยให้หยุดเทรด

ถ้า bridge ตอบช้า/ข้อมูลเก่าเกิน 900 วินาที → **ตัดสินใจได้เลยว่า "ไม่มีสัญญาณ"** ไม่ต้อง fan-out (ประหยัดเวลา)

## Phase 1 — Fan-out (4 subagent พร้อมกันในข้อความเดียว)

| # | บทบาท | ขอบเขต | สิ่งที่ต้องตอบ |
|---|---|---|---|
| S1 | XAU analyst | XAUUSD M5+M15 | bias, entry, invalidation, SL, TP, RR |
| S2 | BTC analyst | BTCUSD M5+M15 | เหมือนกัน |
| S3 | ETH analyst | ETHUSD M5+M15 | เหมือนกัน |
| S4 | Macro/News/Session | ข่าว, ปฏิทิน, session, spread | ความเสี่ยงข่าว + ช่วงเวลาที่ไม่ควรเทรด |

### กติกาที่ต้องฝังในทุก subagent prompt
- **อ่านอย่างเดียว**: ห้าม `docker compose`, ห้าม `docker stop`, ห้าม `main.py --mode=mt5`, ห้ามแก้ไฟล์ (ยกเว้นไฟล์ที่ระบุให้เขียน)
- ใช้ข้อมูลจาก bridge endpoint เท่านั้น ห้ามเดาราคา/ข่าว
- ต้องระบุ `data_age` (วินาที) ที่ใช้
- ถ้าข้อมูลไม่พอ → ตอบ `WAIT` ทันที ไม่ต้องพยายามหาเหตุผลให้เข้าเทรด
- ห้ามคำนวณ lot (ยังไม่รู้ %ความเสี่ยงของผู้ใช้)

### Output contract (บังคับ — ตอบสั้น ไม่เกิน 12 บรรทัด)

```
SYMBOL: XAUUSD
BIAS: LONG | SHORT | WAIT
ENTRY: <ราคา หรือ "รอเงื่อนไข ...">
INVALIDATION: <เงื่อนไขที่ทำให้แผนผิด>
SL: <ราคา> | TP: <ราคา> | RR: <1:x>
REASONS: 3 bullet สั้น ๆ (ระบุว่ามาจากกรอบเวลาไหน)
DATA_AGE: <วินาที>
CONFIDENCE: LOW | MID | HIGH — เหตุผล 1 บรรทัด
```

## Phase 2 — Merge (ผมทำ, ~2 นาที)

1. รวมเป็นรายงาน 6 ส่วนตาม `PROMPT-TRADING-ANALYST.md`
2. **ถ้าสัญญาณขัดกันข้ามสินทรัพย์** (เช่น BTC LONG แต่ ETH SHORT) → ระบุว่าเป็น "correlation conflict" ลดความมั่นใจ หรือเลือก WAIT
3. ถ้าข้อมูลสดแต่ไม่มีเงื่อนไขเข้า → `WAIT` เป็นคำตอบที่ถูกต้อง
4. ต่อท้ายด้วยบันทึกลง `journal/3h_review_log.md` (append):
   ```
   ## YYYY-MM-DD HH:MM (UTC+7)
   - bridge: OK/STALE | data_age: Ns
   - XAU: BIAS | BTC: BIAS | ETH: BIAS
   - plan_changed: yes/no | เหตุผล 1 บรรทัด
   - next_check: HH:MM
   ```
5. ถ้ามีแผนจากรอบก่อน → ระบุ **คงเดิม / ปรับ / ยกเลิก** เสมอ

---

## Phase 3 — ปรับกลยุทธ์ (ทำทุก 3 ชม. ถ้ามีหลักฐาน)

**เป้าหมาย:** ลูปเทรดยังวิ่ง — ปรับแล้วรีสตาร์ทเฉพาะเมื่อ config/โค้ดเปลี่ยน

ตรวจจาก log + ไม้จริงใน 3 ชม. ที่ผ่านมา แล้วเลือกได้ **อย่างมาก 1 การปรับ**:

| สภาพ | ปรับที่อนุญาต |
|---|---|
| 0 ไม้ ทั้งรอบ ทั้งที่มีเทรนด์ชัด | ผ่อน 1 เงื่อนไขเข้า (เช่น RSI band) หรือเปิด cadence pacer ชั่วคราว |
| แพ้ติด ≥ 3 ไม้ / expectancy รอบนี้ติดลบชัด | เข้ม 1 เงื่อนไข หรือปิด pacer |
| sizing reject ทั้งรอบ | ไม่ฝืนลด SL ให้แคบกว่า 1 ATR — บันทึกว่าทุนยังเล็ก |
| ไม่มีหลักฐานใหม่ | **คงเดิม** — ห้ามหมุนพารามิเตอร์ทุก 3 ชม. |

**ห้ามปรับในรอบ 3 ชม.:**
- เปิด BTC/ETH M5 (sweep ติดลบหนัก)
- เปิด daily -5% cutoff กลับมา (ผู้ใช้สั่งปิดแล้ว)
- ส่งคำสั่งซื้อขายมือนอก loop
- เปลี่ยนมากกว่า 1 ปุ่มต่อรอบ

ถ้าต้องรีสตาร์ทลูปหลังแก้โค้ด: ฆ่า process เก่าแล้วสตาร์ทคำสั่งเดิมทันที ห้ามเว้นช่วงนาน

## Failure handling

| อาการ | ทำอะไร |
|---|---|
| subagent ไม่ตอบใน ~5 นาที | ใช้ข้อมูลดิบที่ผม snapshot ไว้แล้วสรุปเอง ไม่รอ |
| bridge ล่ม | รายงาน DOWN + ห้ามเสนอแผน (ไม่ใช้ข้อมูลเก่า) |
| ข้อมูลเก่า > 900s | ตอบ "ข้อมูลล้า — งดวิเคราะห์" |
| ชน −5% ของวัน | **ไม่หยุด** (ผู้ใช้ปิด cutoff แล้ว) — รายงาน P&L แล้วเทรดต่อ |
| ลูป MT5 ตาย | สตาร์ทใหม่ทันที ห้ามรอรอบถัดไป |

## Known issues (ตรวจพบ 2026-11-09)

1. **ชื่อพารามิเตอร์ของ bars endpoint (แก้แล้ว)**: ต้องใช้ `?symbol=XAUUSD&timeframe=M5` — **ไม่ใช่ `tf=`**
   ถ้าใช้ชื่อผิด FastAPI จะเมินพารามิเตอร์นั้นแล้วคืนชุด M15 (default) ทำให้ดูเหมือน "M5 ให้แท่ง 900 วินาที"
   ตรวจแล้ว 2026-11-09: `timeframe=M5` → 120 แท่ง ห่าง 300 วิ, `timeframe=M15` → 60 แท่ง ห่าง 900 วิ ✅
   **ข้อจำกัดที่ยังเหลือ**: M5 มีเพียง 120 แท่ง และ M15 60 แท่ง → **EMA200 คำนวณไม่ได้ทั้งสองกรอบ** ให้ใช้ EMA20/50 และระบุว่า EMA200 ขาด

2. **News feed fail-open**: `ff_calendar_cache.json` = null (FF ตอบ 429) และ `news_calendar.py` จะเทรดปกติเมื่อไม่มีปฏิทิน
   ผลกระทบ: news blackout ไม่เคยทำงาน → ต้องเช็กข่าวเองทุกรอบ

3. **XAU ปิดเสาร์–อาทิตย์**: แท่งสุดท้ายวันศุกร์ ~21:45 UTC; เปิด ~22:00–23:00 UTC วันอาทิตย์ (05:00–06:00 ICT)
   ช่วงเปิด spread ถ่าง 3–10 เท่า → ห้ามเปิดไม้ใหม่จน spread กลับปกติ (~05:20 ICT)

4. **Crypto 01:00–05:00 ICT**: สภาพคล่องบาง, liquidation wick สูง → ลดขนาดหรือรอ; ETH BB reversion เสี่ยงสุด

## กติกาความปลอดภัยที่ห้ามละเมิดทุกรอบ
- ไม่ส่งคำสั่งซื้อขายมือนอก loop ของระบบ
- ห้าม `docker compose down` / ห้ามหยุดลูป MT5 ยกเว้นเพื่อรีสตาร์ทหลังปรับกลยุทธ์
- ไม่สร้างตัวเลขราคา/ข่าว/สถิติขึ้นเอง
- ระดับความมั่นใจ ≠ การรับประกัน
- ปรับกลยุทธ์ได้เฉพาะตาม Phase 3 (มีหลักฐาน + อย่างมาก 1 การเปลี่ยนต่อรอบ)
