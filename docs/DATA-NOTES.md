# DATA-NOTES — เรื่อง시간ของข้อมูลที่ต้องรู้ก่อนทำ backtest

## 1. CSV ใน `data/` เป็นเวลา **Asia/Bangkok (UTC+7)** ไม่ใช่ UTC

ตรวจสอบ 2026-11-09 จาก `data/xauusd_m5.csv` โดยตรง:

| หลักฐาน | ค่าที่เห็นในไฟล์ | แปลว่า |
|---|---|---|
| แท่งต่อชั่วโมง | ชม. 0–3 เต็ม, **ชม. 4 มี 2 แท่ง**, ชม. 5 กลับมาเต็ม | เบรกประจำวัน 04:00–05:00 = 21:00–22:00 UTC ✅ ตรงกับ NY close |
| ปิดสัปดาห์ | เสาร์ 03:45 (แท่งสุดท้าย) | = ศุกร์ 20:45 UTC ✅ |
| เปิดสัปดาห์ | จันทร์ 05:00 | = อาทิตย์ 22:00 UTC ✅ |
| Volume peak | 19:00–22:00 | = 12:00–15:00 UTC ✅ London/NY overlap |

**กฎ**: ก่อนใช้ตัวกรอง session/hour กับ CSV ต้อง **ลบ 7 ชั่วโมง** เพื่อให้เป็น UTC

## 2. แต่ข้อมูลจาก bridge เป็น UTC จริง (epoch seconds)

- `/api/mt5/bars` คืน `timestamp` เป็น epoch UTC → โค้ด live ไม่ต้องแปลง
- **ห้ามเอา CSV ไปผสมกับ bridge bar โดยไม่แปลงโซนเวลา** เดี๋ยวจะเพี้ยน 7 ชม.

## 3. กับดัก data_loader (แก้แล้ว)

`backtest/data_loader.py` เดิม: ถ้าดึง Yahoo ล้ม จะสร้างข้อมูล **synthetic** แล้วเขียนทับ CSV จริงที่ path เดียวกัน
→ แก้เป็นเขียนลง `data/_synthetic/` เท่านั้น และ log ระดับ error

ถ้าเห็นไฟล์ใน `data/_synthetic/` = แปลว่ามีคนรัน backtest ตอนเน็ตล่ม และผลรอบนั้นเชื่อไม่ได้

## 4. อายุข้อมูล

CSV ปัจจุบันครอบคลุม **2026-07-10 ถึง 2026-09-19/23** (~7 สัปดาห์ก่อนวันนี้)
- backtest ทั้งหมดจึงเล่าถึง regime ก.ค.–ก.ย. เท่านั้น
- อย่าใช้ผล backtest พวกนี้ยืนยันสภาพตลาดปัจจุบัน

## 6. ก่อนใช้ตัวเลขใด ๆ จาก backtest

1. แปลงเวลาเป็น UTC ให้ถูก
2. หัก spread จริง (ยังไม่มีในข้อมูล — bridge ไม่ส่ง spread)
3. แยก out-of-sample — อย่าดู in-sample แล้วสรุป
4. ระบุว่า sample ทับซ้อนกัน (overlapping windows) ทำให้ p-value เล็กเกินจริง
